## How updates work

The owner makes all repository commits manually. Routine documentation and ad hoc updates are researched and queued without automatically creating an archive. **The command `Update games` explicitly authorizes a ZIP every time it runs**, without a second request; for all other changes, produce a ZIP only when the owner explicitly requests one. Every delivery must be a **ZIP containing every file in the repository**, both changed and unchanged, preserving repository-relative paths, plus a suggested **commit message**. The owner extracts it at the repository root, inspects the changes, and commits/pushes manually. The assistant may **read** the repository but must never write to GitHub.

**Default file access and ZIP workflow:** Use the **read-only GitHub connector as the first-choice source** for current repository files; do not first attempt direct container downloads. Reuse only blob-hash-verified local copies, and validate complete-documentation ZIPs before sharing them. Follow [default connector access and ZIP packaging](AGENTS.md#default-github-connector-workflow-and-offline-zip-packaging). **If a technical obstacle blocks work, stop, report it and ask for help; do not embark on a complex workaround** (see [technical-detour checkpoint](AGENTS.md#technical-blockers--owner-checkpoint)).
