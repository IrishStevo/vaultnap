# VaultNap

A place to keep track of games that three friends might play together on **Windows 11 gaming PCs**. We mostly use Steam, but other PC storefronts are fine when a game isn't available there.

## Game shortlist

**[Browse the game list →](games/README.md)**

| Section | Meaning |
| :--- | :--- |
| [Possible Games](games/README.md#possible-games) | Games we consider ready to play together |
| [Early Access](games/README.md#early-access) | Games in Early Access that might benefit from more development before we play |
| [Coming Soon](games/README.md#coming-soon) | Games not yet released, including into Early Access |
| [Played](games/README.md#played) | Games we have previously played together; retains each title’s original `Who` attribution |

The shortlist is a set of **candidates**, not a verified list of games supporting three-player co-op. Platform support, player counts, release status, and store review numbers may need checking before we choose a game.

## How updates work

The owner makes all repository commits manually. Proposed updates are discussed in chat and delivered as a **ZIP archive containing the complete repository documentation set** (including unchanged documentation files), plus a suggested **commit message**. Extract the ZIP at the repository root, inspect the changes, and commit them yourself. The assistant may **read** the repository but must never write to GitHub.

## Commands

| Command | Purpose |
| :--- | :--- |
| **Update games** | Refresh Steam review percentages and counts, Early Access timelines/status, and Coming Soon release timing **for games already in the catalog**. Re-sort and reconcile the review snapshot; do not discover or add new games. See [Update games](docs/UPDATE_GAMES.md). |
| **Find new games** | Research new Windows PC co-op games across **Possible Games**, **Early Access**, and **Coming Soon**; check three-player suitability and exclusions; present candidates for approval before adding them. See [Find new games](docs/FIND_NEW_GAMES.md). |

11. **Early Access timeline checks.** `Start` is the actual Steam Early Access launch date, not the 1.0 release date. `Est. End` concise: show the stated date/period without `(est.)` or `(planned)`; for a range show **only its latest/upper-end date or period** (e.g. `2028–2029` → `2029`, `Late 2027–Late 2028` → `Late 2028`). `n/a` means no usable current timing. 12. **Release status and section transfers.** When asked to check Early Access membership, verify current Steam status and move any title that has reached full 1.0 or launched outside Early Access into `Possible Games`, retaining its original link, description and latest existing review figures unless specifically asked to refresh them. 13. **Coming Soon release timeline and sorting.** `When` is the developer/publisher's latest announced date or period for the game's **first public release** (including an Early Access launch, if that's how it will first become available), not a playtest/beta date. Check the current developer/publisher announcement and Steam store page; prefer the official developer-stated date over a region-specific store date, and document differences. Keep the catalog concise without `(est.)` or `(planned)`; for a stated date range use only its **last/upper-end** date or period (e.g. `Q2–Q3 2027` → `Q3 2027`). Use `n/a` when no current usable release target is available. **Always sort Coming Soon by release timing ascending (soonest dates/periods first), with all `n/a` entries at the end in alphabetical order by game title.** For equal known dates/periods, preserve existing relative order. Treat year- and quarter-only dates as ending on their last possible calendar day for sorting, not as asserted exact release dates. On each release-date update, reapply this sorting. **Early Access prefix:** If the developer/publisher confirms that the game’s first public release will be in Early Access, put `EA ` before the announced date/period in `When` (e.g. `EA Feb 8, 2027`, `EA Late 2027`). Apply the prefix to confirmed Early Access *release plans*, not betas, demos, playtests, campaign/edition preorder early unlocks, or similar limited-access offers before a full release. Do not infer Early Access merely from a future date. If the EA release is known but no timing is available, display `n/a` without a prefix; keep full-release first launches unprefixed. **Sort by the calendar period/date ignoring the `EA` prefix**; put unknowns last. Record original source, distinctions between confirmed dates/targets and uncertain schedules, and the check date in `docs/PROJECT_CONTEXT.md`.
